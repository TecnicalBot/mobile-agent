## What's new

- Chat tool modes keep every request lean: `/video` adds video and audio tools, `/docs` adds document tools, and `/general` resets to core tools. Modes stack (a PDF-to-video task can use both) and stay on for follow-ups. If a tool is hidden, the agent can still find and enable it on demand.
- Small-context models, including 4k on-device and Ollama models, now fit their window: optional instructions and tool families are trimmed automatically instead of pushing the prompt past the limit.

- Tool steps in the chat trace now use purpose-built preview cards — checklists for tasks, Q&A for questionnaires, file and schedule cards, voice and narration lists, link previews, and search results — instead of a plain text summary.

- LFM3 1.7B is now available in the on-device model catalog.
- The composer now continues bulleted and numbered lists when you press return, including nested lists.
- Long videos can now be storyboarded and mix-checked before export: scene previews work across the whole video, and audio checks cover the full 10-minute render limit instead of stopping at 45 seconds.
- The agent no longer manages custom agents through a tool; agents are created and edited in Settings > Agents.
- The task (subagent) tool now accepts a `model` ref, and its instructions list every available provider and model, so the agent can pick the right model for a delegated task instead of always inheriting the current one.
- The library is now searchable and organized by chat: browse every file, filter to images, video, or audio, and jump to the media a specific chat created or used. Older references and generated images are recovered automatically, and preview artifacts stay hidden.
- Import several skills at once from a single ZIP bundle instead of adding them one file at a time.
- The catalog now includes opt-in, no-auth MCP presets for DeepWiki, OpenAI Developer Docs, and AWS Knowledge, plus writing and design skills for frontend design, web design guidelines, doc coauthoring, internal comms, and Supabase Postgres.

## Fixes

- Chats no longer go blank while a reply is running. Long OpenCode sessions now keep every message on screen instead of dropping rows until the turn finishes.
- Opening a chat now stays on that chat. Background refreshes, reconnects, and a leftover notification tap can no longer switch you to a different conversation a few seconds later.
- Downloading an on-device model no longer throws a text-rendering error in the model list, and the download button now shows the live percentage so progress is visible while it runs.
- Tapping "Use model" on a model that needs more RAM than the device has no longer kills the app: it asks first, then loads with the CPU backend instead of the GPU delegate that copies the whole graph into memory.
- Running tools now show a live "Running X" row in the chat trace as soon as the call starts, instead of appearing only after it finishes (or showing just a generic Thinking indicator), so long or stuck calls are visible.
- Prior reasoning steps are no longer replayed to the model on every follow-up, removing SDK warnings and unnecessary context use.
- On-device models now run on a newer LiteRT-LM runtime, fixing loads that failed with a weights error.
- On-device models are pinned to exact, verified file revisions, so a catalog refresh can no longer point at weights the app cannot run.
- On Android, downloaded on-device models that no longer match the catalog are cleaned up automatically instead of failing to load.
- Stopping a reply now dismisses the keyboard, and canceled runs no longer raise unhandled promise rejections.
- Starting a new chat with a harness model now stays on that harness instead of silently falling back to the direct API. This fixes new OpenCode chats failing with a free-model rate-limit error while existing sessions kept working.
- Switching to any OpenCode harness model now routes the chat through the harness, and reopening a harness chat keeps it there instead of sending the next prompt through the direct API.
- Switching a harness chat back to a normal model now sticks: the chat records the normal model immediately, so reopening it no longer jumps back to the harness.
- GPT-5.6 and GPT-6 models now work on the OpenAI Codex sign-in provider. Their requests use OpenAI's lite Responses contract, which rejects the old system-instructions field, so those models failed with a system-instructions error after leaving a harness chat.
- The thinking indicator now appears only while the model is actually reasoning, hides while tools run, and repeated calls to the same tool collapse into one expandable row.
- Dismissing the keyboard no longer leaves empty space below the chat, including after sending a message.
- Large folder imports now copy files natively instead of loading them into memory, avoiding out-of-memory crashes.
- Video render progress now appears only in the chat that started the render instead of every chat.
